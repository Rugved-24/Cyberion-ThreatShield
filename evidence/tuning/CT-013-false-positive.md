# CT-013 false-positive tuning record

Behaviour: Process access to LSASS by a non-system caller
Shipped rule: `rules/windows/sysmon_process_access_lsass_memory.yml`
Generated by `scripts/tune.py`. Do not edit the figures by hand.

## Observed false positives

The untuned logic produced 7 matches, of which 7 were attributed benign activity and 0 were the expected attack evidence.

## Change made

Added two exclusions on the recorded call trace: the logon session manager module lsm.dll and the memory compression driver sysmain.dll.

## Attack evidence that must survive the change

Declared evidence: none; no attacker instance of this behaviour is present.
Attack matches retained after tuning: 0 (none).
Attack matches lost by the change: 0.

## Trade-off accepted

A malicious process that injected code into lsm.dll or sysmain.dll would be suppressed, because the exclusion matches the module in the trace rather than the identity of the caller. A production deployment should allow-list by signed binary path instead. The rule now matches nothing in this telemetry, so it is retained as an untested candidate and T1003.001 is left at Not Covered rather than being claimed as detected.

## Observations

- Before: every match was ordinary Windows activity, so the untuned rule had a false-positive rate of one hundred per cent in this telemetry.
- After: the rule is silent here. That is a precision improvement, not a detection success, and the two are recorded separately on purpose.
- The access rights in the excluded records were query-information and memory-read handles consistent with the attributed Windows callers, which is the reason for the exclusion and not the process name alone.

## Comparison population

These recordings are adversary-emulation captures. The records listed here were attributed to ordinary Windows or vendor activity using fields present in the record itself. They are not a separately collected clean environment, they are not exhaustive, and they are not a substitute for one. A client deployment must collect its own baseline before relying on any false-positive rate in this file.
