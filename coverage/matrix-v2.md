## Scoring contract

| Score | Label | Mechanical condition |
| --- | --- | --- |
| 2 | Covered | A rule matched its declared attack evidence **and** a tuning case shows the tuned rule with zero residual benign matches. |
| 1 | Partially Covered | A rule matched its declared attack evidence, but no measured benign comparison exists for that technique. |
| 0 | Not Covered | No rule matched declared attack evidence, or no rule exists. |

A rule with an empty declared evidence list can never score 1 or 2. That is why
CT-013 and CT-014 stay at 0 even though both were authored, tuned and tested.

## Evidence gaps and the minimum dataset needed

### T1547.001

No registry record in DS002 writes a CurrentVersion\Run or RunOnce target; the reviewed registry events cover Internet Settings, Delivery Optimization and notification keys only. The only 'Startup' text in the capture is unrelated. Minimal new dataset: a Sysmon-instrumented capture with event 13 writes to HKLM\...\CurrentVersion\Run plus the resulting execution of the written value. Minimum acceptance: one labelled run-key write and one process creation whose parent or command line references the written value.

### T1110.003

Neither capture contains Security 4625, so there is no authentication-failure series at all, and the recordings are too short to characterise a spray. Minimal new dataset: an authentication log spanning at least one hour with Security 4625, covering one spray against ten or more distinct accounts, plus a matched benign set of ordinary user password typos.

### T1486

No labelled encryption-for-impact sequence exists. Generic file operations in Sysmon event 11 are not evidence of encryption, and this project's name is not evidence either. Minimal new dataset: a documented safe-emulation recording showing the rename or overwrite pattern against known file types together with the process that performed it.

### T1047

DS002 records three WMI 5857 provider-start events and one WmiPrvSE.exe process creation, which is provider startup rather than an adversary WMI operation. No rule was written because a WmiPrvSE rule would match ordinary Windows on every host. Minimal new dataset: a WMI-Activity 5858 or 5861 operation record with an attributable process, or a child process created through WMI.

### T1053.005

The only Task Scheduler record in DS002 is event 129, a task deletion, so there is no task creation or action definition to build on. Minimal new dataset: Security 4698 or 4702 with the task XML action and a Sysmon 1 process creation for the task binary, plus a benign scheduled-task baseline.

### T1071.001

Deliberately left without a rule. T1071.001 is the reserved gap for HUNT-002, which must run before any rule is written so that the hypothesis is recorded independently of the detection. The evidence is DS002:1073 creating the process, DS002:2513 connecting it to 10.10.10.5:80, and DS002:1827 for the script. See hunts/HUNT-002.md.

## What this matrix does not claim

- Tactic labels are ATT&CK taxonomy. They do not assert that the objective occurred
  in these captures.
- An unlisted technique is unassessed. 12 of the technique's sub-techniques and the
  rest of the ATT&CK matrix are out of scope for this engagement.
- Partially Covered does not mean the technique is detected in a client environment.
  It means a rule matched real attack telemetry here and its false-positive rate is
  unmeasured, because the recordings contain no separately collected clean
  environment. See `evidence/tuning/benign-baseline.json` for exactly what was used.
- The two tuned rules that now match nothing were tuned against benign activity,
  which is a precision result and not a detection result.
